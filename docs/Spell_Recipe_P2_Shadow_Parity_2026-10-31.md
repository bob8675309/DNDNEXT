## Mission and scope

P2 compares **the existing server RPCs as golden operational behavior** to synthetic P1 recipe plans, before any shadow evaluator is allowed to execute or any new cast route is introduced. This is a source/behavior contract inventory, not a behavioral proof: we read current SQL definitions, repository source, React dispatch and P1 fixtures, but did **not** cast against production or run signed-in browser tests. The XPHB 2024 rules are the intended source semantics; a current RPC discrepancy is a parity finding, **not** an instruction to copy a suspected bug into a new engine.

Authority chain that must be matched per example: canonical `spells_catalog.spell_key|source` + character assignment/grant -> class/profile + slot context -> authenticated controller, turn and valid target -> server geometry/cover -> server roll/save/damage -> spend action/slot in same transaction -> `encounter_command_requests`, `encounter_combat_log`, encounter version, slot bridge -> visibility-filtered result and Realtime UI. P1 has **none** of those transactional or authorization powers.

## Parity blockers / discrepancies (not fixes in this PR)

1. **CANTRIP-LEVEL:** Live Fire Bolt, Sacred Flame, Acid Splash and Word of Radiance explicitly use `v_profile->>'classLevel'` in their damage-tier selection; the P1 `character-level-tiers` and 2024 rules intend **total character level**. Eldritch Blast staging UI also passes `spellProfile.classLevel` to beam planning. Establish single-class and multiclass fixtures, source of reliable total level, and expected 5/11/17 thresholds before changing behavior. This is a concrete implementation discrepancy, **not yet a reproduced live multiclass failure**.
2. **CHOSEN-EMANATION:** P1 Word of Radiance uses `target:"each-affected"` without expressing player-selected exclusions. Must add reviewed chosen-set semantics or fail closed before any P2 evaluator is marked behaviorally equivalent.
3. **PROJECTILE-IDENTITY:** Magic Missile's current dart-by-dart independent roll and mitigation cannot be replaced by a pooled damage expression. The P1 loop expresses separate projectiles, but has no verified attack-free slot lifecycle or reaction Shield resolution.
4. **AREA-ORIGIN:** Point-origin spell cover is computed from selected impact hex to the target; cone/line cover from caster; **origin fields alone do not perform LOS/cover**. The planned shadow contract must name both stages.
5. **TIMING / TRANSACTION:** P1 has no authenticated grant checks, locks, action/bonus action, slot mirror, idempotency, logs or Realtime. Do not perform independent mock writes or infer concurrency proof from pure graphs. The historical common-effects calculator is not a replacement.
6. **FALLBACK:** Many live functions decline affected targets with conditions, defeated occupants, multiple slot pools or unimplemented reactions. An unavailable feature remains **GM-assisted**; a structural success must never spend resources and silently omit an effect.
7. **SOURCE / RULES:** Repository SQL and live RPCs are an operational oracle, not independent proof that all official 2024 edge cases are correct. Validate rules/source text and licensing per spell before publishing recipes.
