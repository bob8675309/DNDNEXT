This is real dated evidence, not a fake automated claim. Later source documents also record per-spell **transactional postdeploy acceptance ending in ROLLBACK** for many 1J–1Z adapters. Those are separate from persistent smoke logs and from today's browser acceptance.

**Read-only DnDWeb recheck, 2026-11-07:** Four rows named \`Milestone 2 Durable Smoke Encounter\` were observed:
- One **resolved** Round **6**, Version **64**, with **4 participants, 18 combat-log rows, 46 request rows, 2 spell-slot rows, 0 currently active Conditions/timed effects**. Thus the earlier “active Round 6 / Version 63” document describes the *historical checkpoint*, **not current state**.
- Three other older encounters are **archived** (Round 0/Version 11; Round 1/Version 12; Round 1/Version 22). None should be reset/restarted for this audit.

Stored summary examples explicitly include **Fire Bolt, Sacred Flame, False Life, Magic Missile, Acid Splash, Healing Word, Dodge, Dash, weapon hits and Opportunity Attacks**. These logs substantiate actual prior execution of **several** spells, **not all 19**, and do not alone prove cross-account Auth/replay/visibility correctness.
- **No separate multi-user-smoke-named encounter** was returned by the same name/settings query at this checkpoint. This is an observed no-row result under that filter, **not** proof no separate testing occurred elsewhere in history.

**Current regression source:** \`scripts/validate_tactical_spell_suite.mjs\` invokes **48 individual validators** (combat/spell/equipment/resource and multiplayer smoke navigation/setup). The smoke setup validator checks RPC wiring/guarded preparation; it **does not start or simulate combat**. The suite's source/static/API-oriented checks are **not equivalent** to running all 19 spells on a live, authenticated multi-user browser. Each 1J–1Z ledger must retain its own rollback matrix and PR/source evidence. Re-run in **disposable local PG17 + GoTrue** or pre-approved isolated staging, NOT by mutating historical production smoke rows.

## Actual gaps — do not call these “missing deployed code” without reproducing them

1. **A complete general recipe interpreter and release registry** are not on main; held #309/#312 remain drafts. The fact that the imported \`spell_effects\` table has 1037 descriptive rows with \`effect_index=0\` does NOT invalidate the 19 deployed reviewed RPC adapters.
2. The old generic common-character-effect arithmetic/adapter/real-catalogue parity chain is **archived, not merged**, as are optional attunement consumer gating, Physical Specimen's full remaining benefits, P2 shadow parity and Eldritch Blast.
3. **Original source-rule correctness is distinct from matching the current RPC:** held [P2 shadow parity ledger](https://github.com/bob8675309/DNDNEXT/blob/26d2f278b9e85e8fc0b0c04307b7a87bdd2e8254/docs/Spell_Recipe_P2_Shadow_Parity_2026-10-31.md) flags some installed cantrip tiers derived from \`classLevel\` instead of total character level and source/target exception questions. These are **documented review issues**, not fixed by this investigation.
4. **Core replay and concurrency security:** existing live command ledger lacks typed \`request_intent\`; held P2 original signed baseline reproduced an unauthorized/cross-intent cache issue in a disposable local fixture; #317 global encounter/participant/resource/trigger lock research remains held. The historical Round 6 smoke test is **not** multi-account cross-command release proof.
5. **Browser/coverage gaps:** historical smoke logs exercise only a subset, not all 19; 1Z Lightning Bolt had no permanent eligible test actor; separate true three-account smoke session not observed in the current filtered live query. Concentration, persistent zones, Shield reaction, hearing-only targeting, conditioned target exceptions and unsupported catalogue spells remain GM-assisted. Future tests must avoid resetting preserved production encounters.

## Decision and ONE NEXT BOUNDED ACTION

The prior “P1-only extraction” recommendation is **not wrong**, but was **incomplete**. Before spending a session moving P1 source to main, preserve a **single exhaustive source→mechanic→canonical SQL→Postgres/JS validator→dated rollback/smoke→current live-function→gap map** for **the 19 current adapters and the already-live effect primitives**. First implementation slice should be a **pure, free, read-only CI-backed inventory/check** on a new isolated branch that fails on disappearing keys/RPCs/source validators and explicitly records which entries have *real smoke evidence* versus *only historical transactional rollback*. It must **not cast in production, restart smoke encounters, install old archived SQL, mutate game records or weaken source validators**. Only after this preservation gate is reviewed should a separate new-main-based P1 pure parser extraction be proposed for explicit owner merge approval.

No PR merge, SQL/data/grant mutation, deployed UI, world/town-map change, AI activation, automation cost or paid API call is authorized by this document.
