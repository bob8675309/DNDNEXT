# Passive equipment source eligibility — staged read-only gate (2026-10-24)

**Status:** Draft test/internal-helper branch stacked on **#257**, not on main, and **not yet integrated** with #251/#253/#255. The function is intentionally NOT a public RPC, not wired to browser/character-sheet/tactical consumers, and NEVER marks magic active. No production SQL, inventory or UI is changed. Do not merge #257 or this work until attunement rest/prerequisites, source corrections, class cap exceptions and consumer parity are solved.

## Why this gate exists
Existing `private.character_equipment_effects_v1` grants item numeric bonuses from `is_equipped`, not actual attunement. PR #257 adds character-specific bonds and a three/unlimited capacity policy but is not a source-validity engine. The existing equip RPC `set_character_inventory_equipment_v1` only verifies **slot string membership**; it does not enforce shield/armor physical slot category. The equipment UI lists `weapon_1`, `weapon_2`, `weapon_3` as shield-capable slots; currently the legacy numeric resolver still counts a shield in `back`.

**Read-only live catalog observation:** `Ring of Protection|XDMG`, `Cloak of Protection|XDMG`, `Boots of Speed|XDMG`, and `Ring of Fire Resistance|XDMG` have **no** `reqAttune`, `reqAttuneTags`, or `attunement` structured property in DnDWeb, while `Staff of Power|XDMG` has class-tagged `reqAttuneTags`. This is a **missing source-fact/normalization gate**. An absent tag is `unknown`, not `not_required`; correct these with verified authoritative source data, never from inferred rules prose as executable authority. Exact source acquisition/seeding must be audited before repair.

## New private projection
`private.passive_equipment_source_gate_v1(character_id,inventory_item_id)` executes as `SECURITY INVOKER` and is granted **service_role only**. It reads actual owned equipment, only exact canonical item keys (no fuzzy name), checks slot category for recognized armor, shield, ring, boots, cloak and weapon structures, checks player-owner ambiguity and PR #257 bonds, conservatively classifies missing structured source attunement, and identifies valid mundane armor/shield **candidates** independently from magical abilities. It returns a `sourceStatus`, `attunementSource`, `slotStatus`, `bondPresent`, `ownedByCharacter` and `eligibleMundaneBaseAc`. `eligibleForPassiveMagic` and `restAndPrerequisitesVerified` are **always false** until a separate source-validated Short Rest/prerequisite and canonical consumer integration is proven.

### Coverage
Isolated PostgreSQL tests build #257's schemas and private bond state first, then compile this helper and assert the following: ring/cloak missing metadata fail closed; Staff's catalog required tag wins over an instance `reqAttune:false` override; **bond alone** doesn't activate magic; shield in `back` is invalid, but a shield in `weapon_2` and body-chain-mail remain mundane AC candidates; wrong-slot armor rejected; carried/foreign/unknown-key items suppressed; a player account with **two** editable characters is flagged as ambiguous; private helper cannot be executed by authenticated/anon. All data are synthetic, with selected real structured field shapes.

### Not yet implemented — mandatory next slices
1. Real canonical source attunement completeness: 2024 rings, cloaks, boots, and optional/required magic metadata; store positive and explicit negative rules as source-controlled validated fields. Do not casually set all uncommon/rare items to required.
2. Attunement Short Rest receipt (including item contact and no retroactive activation), class prerequisites, Artificer 4/5/6 cap exceptions, curse/transfer/end behavior; do not treat a recorded bond as valid completion.
3. Fix item→slot constraints at the **authoritative equip mutation** and current numeric/tactical consumers together, including legacy `off_hand` rows and current allowed `weapon_* / body / ring_*` slots; no UI-only fix or blind update of existing rows.
4. Bridge this eligibility/read contract to #251→#253→#255's **trusted source adapter**, preserving catalog+instance numeric precedence, Resistance-before-flat-reduction mitigation ordering and mundane gear math. No public client-supplied effect JSON.
5. Production-shaped player/NPC inventory, real character sheet, active encounter, controller ACL, per-use/charge/rest and tactical regression gates. No model/AI tool until authorized read models are proved.
