# Town Handoff Bake — Completed / Archived

Last reconciled: 2026-07-30

Status: **COMPLETE — historical patch-order instructions retired**

This file previously described the intermediate order required while the town profile, merchant, and shared Craft handoffs were generated by build-time patch scripts. That workflow no longer exists.

## Current source-owned state

- `pages/town/[id].js` owns the parent town profile side panel.
- `components/TownSheet.js` owns profile, Shop, and Craft dispatch.
- `components/character/CharacterInteractionPanel.js` owns the shared interaction tabs and delegates the real Class, Spellbook, Shop, and Craft surfaces.
- Town `Open Workshop` enters the shared Craft tab.
- The iframe and legacy `CrafterWorkshopModal` town fallback are retired.
- Merchant/crafter presentation and loading guards are source-owned.
- The Vercel runner validates source and then performs a normal Next build; it does not recreate an intermediate `NpcPanel` state.

## Retired instructions

Do not restore:

- `patch_town_profile_crafter_ui_v1.mjs`;
- `patch_town_crafter_shared_craft_panel_v1.mjs`;
- the old diagnostic scripts;
- the staged intermediate `NpcPanel` validation boundary;
- the former source-bake order described by older versions of this file.

## Current safe-edit boundary

For future town profile/crafter work:

1. inspect `pages/town/[id].js`, `components/TownSheet.js`, and `CharacterInteractionPanel.js`;
2. preserve wrapper props and the shared active-view handoff;
3. patch the smallest source-owned surface;
4. run the town/crafter validators and `npm run build:vercel`;
5. perform a browser smoke test.

Do not mix presentation work with world movement, route advancement, camps, weather, travel windows, crafting formulas, merchant stock, wallet behavior, or inventory consumption.
