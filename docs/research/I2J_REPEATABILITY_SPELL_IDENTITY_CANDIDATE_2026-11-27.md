## Design and controls

- The original Lessons provider requires a different dependent Origin feat. Its historical caller and deferred validator key that rule by child catalog ID. The scratch stage adds a synthetic provider whose rules permit repeats. It carries the source-qualified option UUID through the existing signed advancement and materializer path. The separate fixture tail only admits the scratch provider with exact earned slot and child binding. Lessons and its existing RED remain intact.
- The existing validator resolves the spell/list domain first. The candidate hooks the materializer before effects are written. For a repeatable canonical option with a catalog-configured choice field it derives one normalized key from the validated selection and checks existing grants of the same option, including an earlier grant in the same transaction. Blank or malformed committed discriminators fail closed. The historical signed v5 path already locks progression before acquisition. Nonrepeatable Alert continues to use original ownership denial. Unrestricted Skilled leaves the cross-instance discriminator unset.
- The accepted single and repeatable historical cases keep both old indexes. In the candidate stage only, add an explicit, default-false provenance column. Only source-owned feat inserts in the scratch materializer set it. Replace the legacy label index with equivalent partial uniqueness on unmarked rows and keep the original canonical source-identity index byte-equivalent. Preserve visible labels and existing spell rows. No old rows are reclassified. This marks the writer boundary rather than guessing ownership from source-key spelling.
- Original RED controls require same-spell `23505` on the source-label index and demonstrate the duplicate Wizard list was accepted by the original permissive fixture path. Candidate GREEN covers the canonical same-list rejection, original nonrepeatable rollback, unrestricted Skilled with two owned proficiency claims, and corrected Wizard/Druid retry with shared spell and independent row IDs, casting stats and 1/1 long-rest records. PostgreSQL diagnostics separately prove legacy label and canonical key collision protection. Account, other-character, trigger, Lessons and unrelated function checks protect isolation. The scratch tail and materializer are restored, and the candidate-only schema and synthetic data are discarded by teardown.
