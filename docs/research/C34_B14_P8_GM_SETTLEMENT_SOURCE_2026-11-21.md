## Source graph and defect

Original P6 `public.c34_b14_p6_decide_item_offer_v1(uuid,boolean)` verifies manager, pending state, item-owner CAS, source Forge inventory permission, and NPC kind. It **does not** recheck the Forge sender's current NPC recipient delegation (`can_control || can_edit`) at GM acceptance. P8 `c34_b14_p8_dispatch_item_intent_v1` checks that delegation only at initial Forge donation submission. Thus a GM can approve an already-pending offer after the sender's NPC control has been revoked. Existing P6 was signed and is preserved unchanged (byte hash asserted). This is a release blocker, not an asserted hosted exploit: neither P6 nor P8 is deployed.
