**Source-backed authority decomposition:** An encounter participant controller may use an encounter action through a guarded command; that is **not** the same as a character-scoped delegated NPC/sidekick companion, an item sender, a backpack viewer, an equipment manager, a withdrawal authorizer, or a GM consent decision-maker. These are distinct capabilities with distinct revocation semantics. A stolen/requested item UUID is never proof of ownership, and a client's preferred target does not establish server authority.

## 2. Unresolved owner decisions — never silently infer equivalence

1. **For Forge-owned gear offered to an NPC:** Does a currently assigned direct `controller_user_id` on *one* encounter qualify, or must the sender possess a **character-scoped** permanent companion-control grant? This decision changes the allowed recipient set and after-encounter revocation. The safe **provisional** approach is to require an explicit current character-level delegated-control grant that cannot be inferred from `can_inventory` or backpack visibility. Preserve current source `can_edit` compatibility where PR #312 requires it, but do **not** auto-materialize a `can_control` row from edit rights. The exact policy and creation/rollback migration need owner review.
2. **GM approval versus original P6:** Versioned P8 GM settlement rechecks current source and recipient authorization for accepting Forge-owned gear; original P6 does not. Only one manager decision route may remain EXECUTABLE after cutover. Never revoke sender cancel or player trades by accident.
3. **Status visibility after sender grant revocation:** P14 disposable status returns minimal sender-owned lifecycle even after source recipient delegation is removed. **Owner privacy choice required** before production; status must never reveal NPC private inventory, Story, Forge sheets or secret child request UUIDs.
4. **NPC kind and hidden identity:** P6 accepts a genuine `kind='npc'` that is not Forge-tagged nor hidden; PR #312 also permits delegated combat control for merchants. NPC gifts, merchant personal stock, GM item assignment and merchant combat control must not be merged into a single destination authorization without a designed contract.
5. **Account ownership vs character ownership:** account-to-account sends remain immediate; character-owned items currently allow controlled NPC gifts only in candidate. Do not add cross-Forge-character transfer or immediate NPC gifts without a separate owner decision.
