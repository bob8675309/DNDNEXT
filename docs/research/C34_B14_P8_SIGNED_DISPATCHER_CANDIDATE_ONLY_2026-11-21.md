### P8 child request ID hardening

Original draft derived public P8 batch child request UUIDs deterministically from the parent request UUID and item ID. Because the same public single-intent endpoint accepts caller-chosen request IDs, a signed client could preseed an identical child receipt and potentially make the bulk skip a current source-ownership check, violating intended atomic semantics. Updated batch to use `pg_catalog.gen_random_uuid()` for child-only IDs; stable idempotence continues through the locked private **parent** receipt, not predictable children.
