## 3. Proposed status read contract (NOT IMPLEMENTED)

Proposed versioned read-only public function c34_b14_p14_my_intent_status_v1(p_parent_request_id uuid) in a **disposable** candidate first, not a hosted function name reservation:

1. Read auth.uid() from a genuine signed JWT; no client-provided actor, GM status or role flag. Load the **private P8 parent receipt** and require its actor_id to equal auth.uid(); missing or mismatched requests must not disclose whether anyone else's request exists. A separate existing GM-only queue remains the staff route.
2. Resolve parent→P6 offer via the same UUID for single NPC sends, but use the **private one-to-many link** for bulk. Proposed private link rows: parent_request_id, child_offer_request_id, item_id, ordinal. Enforce unique parent+item, unique child offer ID, FK/consistency with source private P8 receipts and P6 offers where possible. Insert link rows inside the *same existing P8 transaction* as child submission; persist authoritative child UUID before masking client response. No client SELECT/INSERT/UPDATE/DELETE grants or broad RLS policy. A source-authentic signed migration rehearsal must prove integrity, rollback and no guessable child IDs.
3. Compute current status from **the P6 offer row** for NPC-targeted rows (pending, accepted, declined, cancelled); for original immediate player-account sends, accepted is the committed P8 receipt outcome and there is no P6 offer row. Do not treat initial pending as latest status, or trust client-passed status. A missing link/ledger must be a **fail-closed unavailable/inconsistent state**, never a fabricated accepted or pending result.
4. Return a minimally redacted result for original sender: parent request_id, source-known target type, current status and an array of per-item statuses keyed by item UUID or stable position only if source authorization remains valid. No card_payload, private GM Story, character Sheet, other sender UUID, GM-only detail or private child request UUID. For revoked source access, provide at most a reviewed non-sensitive own-request lifecycle response (or deny); this decision must be explicitly role-tested and approved, not inferred. GM actions use their separately reviewed service.
5. Must be a fresh server query after submit, GM decision, cancel, sign-in change and grant change. UI may poll on-demand; no requirement to enable client access to private tables or Realtime. Use auth/session + actor + target + request epoch to reject stale async responses, including global suspended Profile and Town swaps. Never claim a status will eventually change without signed evidence. Replaying P8 request returns the immutable original receipt, then UI independently asks the status reader for current truth.
6. Current P6 has no expired state. If expiration is desired later, it requires a separately versioned state transition, deterministic time authority, concurrent GM/cancel precedence and rollback tests. Exclude it from this initial contract.
