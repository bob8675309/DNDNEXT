## Original source, exact branch and scope

## Source-derived disposable implementation

- New scratch \`t46_p3_p4b_c2b14_p20b_disposable_atomic_town_inscribe_pg17.sql\` requires real local PG17 with original P16/P18, exactly original four plus P20A restrictive inventory RLS, P20A trusted receipt and source tables. Defines one private nonce ledger (no public table grants) and a signed-only \`public.c34_b14_p20b_inscribe_owned_item_v1(uuid,uuid,uuid,bigint)\` with server-derived item metadata.
- Authorization: caller must be real \`auth.uid()\`, base \`inventory_items\` row locked and owned by this player with \`owner_type='player'\`, \`owner_id=self\`, and not equipped. A nonhidden, resting scribe NPC/merchant must be in the requested town, with actual \`scribe\` tag. No client can submit \`craftedInsert\`, recipient, card payload or bonus to this RPC.
- Concurrency: nonce advisory transaction lock; one same nonce/intent yields one result and can replay idempotently; changed intent or different signed actor fails. Competing distinct nonces lock the same source row and only one can consume it. Server \`DELETE\` and \`INSERT\` plus nonce receipt are ONE PostgreSQL statement transaction. Any craft-result insert failure restores original consumed row automatically.
- All SQL objects are scratch-only. Source and guarded authenticated workflow explicitly subscribe to new files; signed P20B runs inside existing P20A runner after P20A direct Town RED/HOLD and before its temporary P19 manager policy and P18 teardown. New signed tests must verify original Town source, foreign/non-present role denial, deliberate insert-trigger post-delete rollback, exact plain-gear result/provenance, same/different nonce concurrency, player equip/private outsider read and total restoration.
