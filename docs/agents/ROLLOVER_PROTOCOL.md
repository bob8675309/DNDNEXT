# Owner-approved DNDNext scheduled agent rollover protocol

Approved 2026-11-24. This is a docs-only continuity registry, not a gameplay change. No paid services or new connectors (including Daybreak). The live saved task definition and branch-local ACTIVE_WORK/HANDOFF_LOG are authoritative; GitHub snapshots support recovery, not automatic overrides.

## Detect and classify
D checks A–C after their hourly cycle. Explicit context-full failure, inaccessible exhausted chat, repeated verified non-delivery with context errors, or owner request may justify rollover. No remaining-token telemetry exists. Unproductive work alone is not proof of context exhaustion: use bounded correction proposals first. A pending/in-progress run is not a failed run.

## Transfer safely
1. Discover all relevant tasks privately with Automations peek; resolve unique enabled role by title, exact ownership in prompt and schedule. Never use a stale ID from a transcript. If multiple enabled matches, stop and reconcile with owner; do not guess.
2. Capture exact live saved prompt, timing mode, timezone, schedule, enabled flag, task/conversation IDs privately; verify actual branch HEAD, changed artifacts and exact CI, latest run status, next bounded task and blockers. Store sanitized checkpoint in role file and append rollover log on this registry branch. No private identifiers or raw transcripts in this PUBLIC repository.
3. Confirm no active run using latest run status. Pause old task before enabling any replacement. Verify disabled; pause does not establish an in-progress run stopped. If run state ambiguous, do not start replacement until clear.
4. There is no task move/reassign API or selectable destination conversation on task create. Creating from a chat may attach to that chat. For genuine fresh-context transfer, the owner opens a NEW chat (prefer same DNDNext project), pastes recovery request below, and asks that chat to create replacement from the old live task definition. D can prepare the checkpoint, pause a confirmed exhausted/idle task, and give the recovery instruction; cannot independently open a fresh interactive chat or guarantee conversation placement. Do not create a replacement in D's own active conversation or use paid agents.
5. Replacement uses same role, exact ownership, saved instructions, timezone, cadence, active hours and timing mode. Adjust past DTSTART to next valid occurrence if necessary, preserving RRULE and schedule semantics. Verify creation success, distinct conversation from retired task and all other active agents, same scope/schedule, and exactly one active task for role. If bound incorrectly, pause the attempted replacement and verify; never let two writers run. If no safe replacement exists, keep a confirmed exhausted old task paused and tell owner; restore a healthy old task only if no replacement active and no conflict. No auto run_now unless owner explicitly requests.
6. Update sanitized registry, role checkpoint, supervisor handoff and append-only rollover history with role, old/new title, time, state, branch SHA, next task and outcome. Actual task/conversation IDs remain private. D uses live task discovery every review (not hardcoded IDs); no need to change all agent prompts for a new ID.
7. At first scheduled run verify actual branch ownership, bounded artifact or concrete blocker, and CI. Do not report successful transfer until creation/placement and enablement verified; first-run acceptance is separately pending until observed.

## Recovery request (paste into a fresh chat)
"Take over as replacement DNDNext Agent [A/B/C/D]. Read https://github.com/bob8675309/DNDNEXT/blob/docs/agent-rollover-registry/docs/agents/ROLLOVER_PROTOCOL.md and AGENT_REGISTRY.json. Discover my original scheduled task privately, read its complete live saved prompt and schedule, confirm its current run is finished and pause it, then create the same role in this new chat with unchanged ownership and restrictions. Verify distinct conversation, one active role, and current repository checkpoint. Update registry and report exact next task. Do not restart completed work or change other agents, production or gameplay."

## Authorization boundaries
D may write ONLY docs/agents/** on docs/agent-rollover-registry (CAS, no force); prepare and coordinate owner-authorized rollover and pause confirmed exhausted idle agents. D remains read-only on engineering branches and production. Replacement creation in a new chat is authorized for the same role only; no fifth active role, no expanded permissions, no schedule expansion, no unsupervised gameplay changes. Agent D itself must be recovered from a new owner-initiated chat if exhausted. A–C continue exclusive branch work; they may read registry but never write it. No automatic prompt changes beyond the explicitly approved same-role continuity replacement. No PR close/merge/rebase, hosted SQL even SELECT, maps, deployments or paid services. If tool access fails, report actual failure and preserve the last safe state.
