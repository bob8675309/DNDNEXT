## Why naive assembly is unsafe

1. **Stage ordering and runtime consumers.** #345 Stage1 narrows character-sheet RLS and defines a player-safe NPC RPC, Stage2 revokes direct SELECT on five character narrative columns for all authenticated roles, Stage3 adds creator/private Story/GM clue and *redefines* the player-safe NPC RPC. The Stage1 implementation alone has an older revealed-raw-secret code path; the Stage3 replacement must be effective before signed player visibility acceptance. Stage2 requires paired migration of Admin and non-Admin consumers, not a solo ACL revoke. `components/NpcPanel.js`, `pages/npcs.js`, Player Profile and original direct readers must be audited alongside it.
2. **Immutable intent is separate from Story content.** #324 copies original public v2/v3 Forge code into private sources, adding immutable replay reservation; the original #345 Story wrapper is not Story-inclusive. #351 replaces that wrapper with source-shaped Story SHA-256 bound to the same nonce. Changed Story-only replay must fail with SQLSTATE 22023, identical replay must return existing character, and identical retry after later authorized Story edit must not overwrite the edited secret. A failed Story write must roll back character+nonce.
3. **Option A cannot silently re-write legacy account data.** **New source-order blocker, November 12:** original I2C requires the #324 private nonce reservation table already exist *and* public v2 remain at original MD5 `0351f0a00acae023278e1b8b065b00c9`, but #324 installs that table then replaces public v2. Thus unmodified I2C cannot run before or after #324; earlier proposed full I2C→I2D ordering is superseded. The new partial rollback-only composer intentionally excludes I2C. A source-specific v1 repair alongside #324 and original I2D needs separately proven RED→scratch GREEN before a complete joint run.  `character_sheets` is canonical; every existing `players.sheet` value, including `{}`, must remain byte-identical. I2C original v1/v2 and I2D private copied v2/v3/Story scratch candidates remove particular mirrors with MD5 guards. They are **not** a complete 34-writer cutover. Check account INSERT/UPSERT writers, legacy readers, Admin/profile interactions, grants, SQL definer/invoker boundaries, and direct authenticated account-sheet UPDATE. Preserve original v1 `UPDATE`→`IF NOT FOUND THEN INSERT` semantics with exact source-original RED then scratch GREEN. Never replace code based solely on similar-looking text. Caller ownership and privacy changes must be signed tested.
4. **Inventory only as a coupled transaction.** Stage4 has four original inventory policy ALTERs and the old CHECK drop in the **same** transaction, guarded by original source MD5 and expected grants. Dropping the old CHECK without those RLS guards can enable forged direct inventory DML. Do not use against hosted DB. Original Forge equipment materializer, RLS, GM access, NPC/merchant role transitions and transfers need signed negative tests.
5. **Original value deferred, not discarded.** #318 Admin permissions/created-notice UI, #312 `can_control` delegation, #317 cross-command lock/replay defense, #309/#312 spell execution, #335 complete browser Forge, future #325 agent, and all 19 deployed XPHB spell adapters remain distinct release tracks. #345's world-map-affecting centered Profile style needs owner visual signoff.
