# DNDNext Agent Opportunities — source-grounded survey (2026-11-05)

**Classification: product research and prioritization, NOT new shipped gameplay AI.** Reviewed the current \`main\` repository tree and the actual source/documents referenced below. The owner requested identification of other agent uses while a separate **development research agent** is prepared on an isolated draft PR. No production AI runtime, provider key, Supabase migration, GM permission change, combat control, NPC autonomous movement or world/town map patch is authorized by this survey.

## Two distinct agent families

1. **Development/operations agents (GitHub/CI)** work with checked-out code, approved test fixtures, source catalogs and CI. First proposal: \`.github/workflows/dndnext-research-agent.yml\`, manual/approval-bound Codex, read-only token, no production credentials, at most two local static repair passes and human-review patch artifact. A later passive no-cost CI-failure notifier and regression coverage reporter might be useful; always-on paid code generation is NOT enabled.
2. **In-game AI agents (player/GM experience)** must use the separately approved local-first, provider-neutral future interface in [DNDNEXT_AI_INTEGRATION_FOUNDATION.md](DNDNEXT_AI_INTEGRATION_FOUNDATION.md), not the Codex development agent. Desired interfaces (\`generateText\`, \`generateStructured\`, \`chooseAction\`) and read-model/context builders are **design-only**, not evidence of installed runtime. Prefer Ollama/llama.cpp adapters and an explicit **AI Off** choice; cloud inference only opt-in. GM/player visibility and actor-known context must be filtered *before* data reaches any model.

## Implementation contracts to preserve

- **Authorization first:** source-authorized, viewer-filtered contexts must be generated by DNDNext. A prompt such as "do not reveal GM secrets" is not an access-control layer. NPC creator/co-editor visibility and separately GM-only secrets are still research-sensitive on #321/#324.
- **One rules authority:** anything that changes HP, initiative, resource slots, inventory, trading, XP, movement, weather, conditions or persistent spell effects goes through original server-authoritative handlers with current actor permissions, immutable intent and transaction locking. Future Actor AI chooses only server-provided eligible actions.
- **Local-first provider separation:** avoid coupling Next.js UI to cloud API credentials. When gameplay AI begins, use a provider-neutral server-side adapter, GM-configurable budget, AI Off and usage limits, per-viewer context filtering, and ephemeral output unless deliberately saved.
- **Human approval for durable game truth:** generated quest hooks, rumors, NPC memories and magic-item drafts must remain drafts until explicitly approved. Never silently make a model response canonical campaign history.
- **Different map authorities:** do not mix world map/route simulation and town-map roster with tactical hex board AI. This audit makes no map code changes.
- **Source/version fidelity:** start with approved 2024 XPHB sources. Never let an agent treat 5etools import descriptions, old docs or UI placeholders as sufficient to bypass canonical source rules.

## Recommended phased rollout

1. **Now:** keep the supervised GitHub research-agent PR read-only/API-off by default. Validate its scope, cost and preview controls. Merge only in a batched owner-approved release; fund and manually dispatch one bounded test afterward.
2. **After Forge + inventory RLS + browser acceptance:** prototype **admin-only local magic-item drafting**, with reviewed structured schemas, authority filtering and no write until GM Save. Existing AI foundation explicitly preferred this as the first in-game AI task.
3. **After NPC Profile privacy and creator grants are accepted:** prototype isolated GM-view NPC conversation **read-only**; then test player-safe visibility and explicit GM reveal permissions. Do not mix GM secrets with actor-known context.
4. **After P1.3 global lock and composable spell/legal-action design accepted:** add a bounded read-only tactical decision *advisor*, then a GM-controlled opt-in Actor AI using the exact same executor as a human. Start with non-combat suggestions and clear refusal/fallback when no valid action exists.
5. **Parallel low-risk improvements:** documentation/asset audits and merchant/route advisories that only report anomalies, never auto-write to world time, character movement or player inventories.
